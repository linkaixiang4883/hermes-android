**Goal:** 把上游 43 个提交（v2.1.7+2147 → v2.1.12+2152）并入本 fork；按用户 2026-10-05 决议收编官方 i18n / 官方 srq、退役语言切换器、重打保留 overlay；门禁全绿 + 真机 QA 后推送 fork。

**Status:** 调研完成，待用户审阅本计划后执行。相关背景：上一轮合并见 `.hermes/plans/2026-09-28_222516-merge-upstream-v2.1.7.md`；仓库 `AGENTS.md §4-5`；技能 `hermes-android-client`。

## 六、分阶段步骤

### Phase 0 — 准备（约 30min）
1. `git status` 干净确认；`git tag pre-v2112-merge HEAD`（后续 diff/计数守卫参照）。
2. 本计划 + 附录随 Phase 1 的 merge 提交一起 commit（或先单独 docs 提交）。
3. 复现冲突面留档：`git merge-tree --write-tree --messages HEAD upstream/main` → `.hermes/plans/attachments/merge-preview-2112.txt`。

### Phase 1 — merge 与冲突解决（约半天）
1. `git merge upstream/main` → `git diff --name-only --diff-filter=U` 为唯一冲突真源。
2. 按 §五 分类解：`git checkout --theirs` 为主 + python 脚本重打 keep-list；`chat_screen.dart` 为最重文件（照 `resolve_chat.py` 模式逐 hunk）。
3. 删除清单执行（§三-B）；全仓 `grep` 确认无孤儿引用（如 `respondToServerRequest`、`app_locale`、`l10nTestDelegates` 在保留代码中清零，剩余的均为上游同名实现）。
4. 花括号配平扫描 + `flutter analyze` 试跑。
5. **imports 迁移**：keep-list 文件统一 `package:hermes_android/core/l10n/l10n.dart`。

### Phase 2 — l10n 收编（约 2-4h）
1. 采用上游 `l10n.yaml`；`flutter gen-l10n` 生成（提交生成文件，CI 用 `--no-pub`）。
2. keep-list 新文案 key 并入上游 `app_en.arb`+`app_zh.arb`（仅 en/zh；其余 8 语种缺省 fallback en，可后续补）。
3. 我方保留测试迁移到 `testAppWithL10n`/`loadTestL10n`。
4. 版本/CI 同步核对：`pubspec.yaml 2.1.12+2152` ↔ `pr-quality.yml REQUIRED_BASE_VERSION_CODE=2152`。

### Phase 3 — 测试全绿（约 3-5h）
1. `export NO_PROXY="127.0.0.1,localhost"`；`flutter analyze --no-pub --fatal-infos` 归零。
2. `flutter test --no-pub` 全量跑；按固定 pattern 修（见 playbook：delegates/fixture/关 socket 等）。
3. keep-list 测试全部恢复；退役测试删除；零孤儿。
4. 与上游测试基线对账（上游新增 `ws_server_requests_test`、3 个 l10n 冒烟等全部在跑）。

### Phase 4 — 构建 + 真机 QA（约 2-3h）
1. `flutter build apk --release --split-per-abi` → apksigner 补签 → `adb install -r`（覆盖、数据保留）。
